# TUSOVA Radio — DJ v1

Один общий эфир и один ведущий одновременно. DJ — отдельный флаг `isDj`, совместимый с VIP и базовой ролью USER/MODERATOR/ADMIN. Администратор назначает его в списке пользователей или редакторе аккаунта. Плашка и рамка сиреневые.

## Как ведётся эфир

Откройте «Радио» → «Студия DJ» → «Начать эфир». Добавьте аудиофайлы в плейлист. Сервер проигрывает их последовательно; закрытие браузера DJ не останавливает музыку. «Открыть заказы» разрешает заказы пользователей; «Следующий трек» пропускает текущий с возвратом резерва. «Завершить эфир» выключает поток и возвращает резервы всех невыполненных заказов.

Звук: изолированный FFmpeg worker → Icecast → `/radio-stream/live.mp3` через Caddy. NestJS обслуживает только команды/метаданные, не поток. Метаданные обновляются каждые 5 секунд, серверная очередь — каждые 3 секунды. Серверный FFmpeg заменяет предложенный в первоначальном плане Liquidsoap для файловой очереди v1. Прямой аудиовход BUTT, микрофон, микшер и несколько эфиров **ещё не реализованы**.

Плеер включается только нажатием пользователя и сохраняется между разделами. При записи голосового/прослушивании другого аудио эфир приглушается. Отзыв DJ, активный бан, потеря worker или API прекращают эфир; worker сам отключается через 30 секунд без heartbeat. Секреты worker/Icecast никогда не выдаются браузеру. Операции защищены UUID эпохи: старый запрос не выключит новый эфир.

## Заказы и кредиты

- Цена по умолчанию **5 кредитов**, изменяется администратором. Перед отправкой цена подтверждается и фиксируется в заказе.
- `/radio/requests`: исполнитель, название, посвящение, необязательный файл; собственные заказы и обезличенная публичная очередь. Максимум 3 активных платных заказа.
- `/radio/studio`: автор/посвящение, защищённое скачивание и предпрослушивание, принятие, отклонение с причиной, загрузка найденного DJ трека для текстового заказа. У DJ до 50 своих активных бесплатных треков.
- Кредиты резервируются атомарно с созданием заказа. Повторный idempotency key возвращает существующий заказ без повторного списания. Резерв становится оплатой после подтверждённого завершения декодирования. Отмена до проигрывания, отказ, пропуск, истечение срока и обрыв возвращают его один раз. DJ не получает доход в v1.
- Аудио: максимум 25 МБ/15 минут, 5 активных файлов на аккаунт, загрузки ограничены по частоте. Содержимое проверяется ffprobe, форматы MP3/WAV/FLAC/Ogg/M4A/WebM; видео и внешние URL не допускаются.
- Приватный `storage/radio`, не публичный `uploads`. Файл доступен владельцу, администратору и ведущему соответствующего эфира **один час после завершения загрузки**. После срока скачивание запрещено, фоновый цикл удаляет файл; история заказа/экономики остаётся. Скачанные DJ локальные копии удалить невозможно. Постоянные вложения профилей/лички/сообществ не затронуты.

## Локальное включение

1. Сделайте копию `infra/radio/.env.example` в `infra/radio/.env.radio.local`. Создайте три разных случайных секрета длиной не менее 32 символов. Не коммитьте их.
2. Создайте `apps/api/storage/radio` с владельцем текущего пользователя. Worker UID 1000 должен иметь право чтения (API контейнер тоже работает с UID 1000). В нестандартном окружении согласуйте UID/группу; не делайте хранилище публичным.
3. Запустите только радио, не соседние проекты:

   ```sh
   docker compose --env-file infra/radio/.env.radio.local -f infra/docker-compose.radio.local.yml up -d --build
   ```

4. В `apps/api/.env` задайте `TUSOVA_RADIO_ENABLED=true`, `RADIO_WORKER_URL=http://127.0.0.1:3006`, `RADIO_WORKER_TOKEN` с тем же значением, `RADIO_STORAGE_DIR=storage/radio`. Если Docker работает на Windows, а API в WSL, используйте адрес локального Windows/Docker-шлюза вместо loopback. Icecast-прокси Next по умолчанию `http://127.0.0.1:3005`; при необходимости `RADIO_STREAM_PROXY_URL` задаётся в `.env.local` **перед сборкой Next**.
5. `npm run db:migrate`, затем перезапустите API/web. Назначьте DJ из админки; обновите его сессию/страницу. Демонстрационные боты управляются отдельным флагом и не влияют на радио.

## Production и повторная публикация

Опубликовано на tusova.su 2026-09-28 в релизе `cf6ee7b`. Миграция применена, радио включено по разрешению пользователя; worker и Icecast запущены, защищённое управление и реальная проверка ffprobe пройдены. Системный Caddy направляет поток на loopback 3005; соседний бот не перезапускался. До начала эфира поток возвращает 404. DJ должен вручную открыть студию и начать эфир; публичный тестовый эфир при выкладке не запускался. Бэкап — `/opt/tusova/backups/20260928-full-release`.

Ниже порядок повторной установки/обновления:

Сначала backup PostgreSQL и сборка/публикация кода через Git. Примените миграцию `20260928130000_radio_dj`. Добавьте сильные радио-секреты и `TUSOVA_RADIO_ENABLED=true` в защищённый production env. Используйте override `infra/docker-compose.radio.yml` вместе с существующими production/shared-host файлами. Запускайте **явно только** сервисы TUSOVA: postgres/api/web/radio-worker/icecast, не Compose Caddy на сервере с системным Caddy. Не останавливайте чужого бота и не используйте `compose down`.

Для системного Caddy на текущем сервере добавьте этот блок **перед общим маршрутом web**:

```caddy
handle /radio-stream/live.mp3 {
    rewrite * /live.mp3
    reverse_proxy 127.0.0.1:3005 {
        flush_interval -1
    }
}
```

В контейнерном Caddy этот маршрут уже подготовлен в `infra/Caddyfile` с адресом `icecast:8000`. Не открывайте 3005/8090 наружу. Установите ротацию логов и исключите `storage/radio` из долговременных бэкапов вложений. Перед публичным запуском согласуйте допустимый музыкальный контент/права на трансляцию. Принудительная остановка эфира и пропуск доступны ведущему, остановка чужого эфира — администратору.

## Проверки

`npm run lint:all`, `npm run build:all`, `npm run test:radio`. Последняя команда создаёт и удаляет **отдельную временную** PostgreSQL-базу, не очищает рабочие данные. По умолчанию только loopback PostgreSQL; для WSL укажите `RADIO_TEST_LOCAL_DB_HOST` с точным адресом проверенного локального Docker-шлюза. Нельзя указывать production DATABASE_URL.

Реальный поток: соберите оба локальных образа с тегами `tusova-radio-worker:dev` и `tusova-icecast:dev`, затем `node scripts/test-radio-stream.mjs`. Тест создаёт отдельную Docker-сеть/контейнеры, проверяет MP3 поток, WAV, завершение/пропуск и защиту путей/эпох, затем удаляет только свои ресурсы.

Остаются реальная проверка полного эфира на Android/iOS (фон/блокировка), нагрузка, широковещательные уведомления о решениях и прямой вход с микрофона/BUTT. Публикация на сервер выполнена.
