# Викторина TUSOVA

Служебный аккаунт `tusova_quiz` («Сова Викторина») задаёт вопросы в комнате `main`. Это независимый от демонстрационных ботов модуль: его можно использовать в production при `TUSOVA_BOTS_ENABLED=false`. ИИ для проверки ответов не используется.

## Включение

1. Применить миграции API: `npm --prefix apps/api run db:deploy`, пересобрать и перезапустить API/web.
2. В окружении API задать `TUSOVA_QUIZ_ENABLED=true`. В production Compose переменная передаётся из окружения/`.env`; значение по умолчанию — `false`.
3. Открыть **Управление → Викторины**, загрузить JSON, нажать «Проверить JSON», затем «Создать новую тему» или «Обновить существующую тему». Новая тема неактивна до явного включения.
4. Включить тему, установить расписание и награду, включить викторину и сохранить настройки. Бот начнёт, когда разрешены время, бюджет и число участников.

До настройки темы/переключателей неожиданных вопросов и начислений нет. Код и локальная миграция подготовлены; production не развёрнут. Локальная база перед миграцией сохранена в `/tmp/tusova-before-quiz-20260928.dump` (режим доступа 600).

## JSON

Скачиваемый шаблон есть в админке и в `docs/examples/quiz.json`.

```json
{
  "version": 1,
  "id": "night-nature",
  "theme": "Ночной мир",
  "questions": [
    {"id": "moon", "question": "Как называется естественный спутник Земли?", "answer": "луна", "acceptedAnswers": []}
  ]
}
```

Максимум 256 КБ / 500 вопросов в одной теме; `id` — 1–64 латинских букв, цифр, `_` или `-`. Тема до 120 символов, вопрос до 500, ответ/вариант до 100. Основной ответ должен содержать минимум три буквы для двух подсказок. Дополнительных вариантов до 20. Повторяющиеся ID и одинаковые нормализованные ответы запрещены. Импорт либо создаёт тему с новым ID, либо явно обновляет существующую, увеличивая её ревизию. Снимок уже начавшегося раунда не меняется при редактировании/удалении темы или награды.

## Правила игры

- Ответ — новое сообщение в `main`, в том числе reply на вопрос или `@tusova_quiz: ответ`. Личка, другие комнаты, старые/отредактированные сообщения, гости и боты не участвуют.
- Сравнивается весь текст после нормализации Unicode, регистра, ё/е, повторных пробелов и внешней пунктуации. «Я думаю, это луна» не равно «луна»; синонимы нужно задать в `acceptedAnswers`.
- Попытка от одного участника учитывается не чаще раза в две секунды. Бан, мут, «Хаос» и список исключённых UUID действуют и для викторины.
- Первый подходящий правильный ответ закрывает раунд. Награда и запись `QUIZ_REWARD` фиксируются одной транзакцией. При одновременных ответах победитель один.
- Две подсказки открывают по одной новой букве в маске. Выбранные позиции сохранены в БД; ответ не открывается целиком. При победе будущие подсказки отменяются. По окончании времени бот публикует ответ без выплаты.

## Настройки

Исходные значения: пауза 300 секунд, раунд 90 секунд, подсказки на 30/60 секундах, награда 5 кредитов, минимум два зарегистрированных участника онлайн в `main`. Все значения меняются администратором. Награда 5 — настраиваемое начальное значение, а не цена заказа песни DJ.

`0 < hint1Seconds < hint2Seconds < durationSeconds`; награда 1–1000, раунд 10–600 секунд, пауза 5–86400 секунд. Есть дневной бюджет, максимум вопросов, лимиты побед и кредитов на участника. Награда и лимиты участника фиксируются в снимке раунда. Общий бюджет резервируется учётом активного раунда; проигранный/отменённый раунд его не тратит. Отмена всё равно учитывается в дневном числе вопросов.

Расписание — IANA-пояс (по умолчанию `Asia/Barnaul`) и 1–14 окон:

```json
[{"days":[1,2,3,4,5],"start":"22:00","end":"02:00"}]
```

Дни: 0 — воскресенье, 1 — понедельник, … 6 — суббота. Ночное окно относится к дню начала: окно понедельника продолжается во вторник до 02:00. Полный день — `00:00–24:00`. Раунд не начинается, если до закрытия недостаточно времени. Минимум участников проверяется перед запуском; уже заданный вопрос дожидается ответа/срока. ONLINE/AWAY/DND считаются по серверному состоянию присутствия.

Последовательный или случайный порядок выбирается среди вопросов с наименьшим числом показов; до исчерпания доступного круга повторов нет. Отдельно задаются повторное использование набора и запрет повторения в часах. Недостаток участников/бюджета/темы отображается в статусе; повторная проверка — через 15 секунд, без спама в чат.

«Пауза», выключение, пропуск и завершение отменяют текущий раунд без награды, с раскрытием ответа. Сохранение других настроек само по себе не снимает паузу. «Продолжить» возобновляет по расписанию. Ручной запуск вне окна требует подтверждения; минимум участников и дневные лимиты сохраняются.

## Надёжность и доступ

Все изменения ведущего сериализованы блокировкой singleton-строки PostgreSQL. Одновременно работает один раунд; второй API-процесс не дублирует вопросы/награды. Сообщения и очередь публикаций записываются транзакционно; у события стабильный ID, клиент удаляет повторную доставку. Возможна повторная доставка одного и того же ID после аварии между отправкой и подтверждением — не повторная выплата.

После рестарта продолжаются серверные сроки. Если раунд истёк в простое, он закрывается без победителя/пачки пропущенных подсказок. Если пропущены оба срока подсказок, публикуется только актуальная вторая маска, а не две сразу.

Ответы/варианты активного раунда доступны только API и администратору. `GET /api/quiz/status` для авторизованного участника возвращает только вопрос, срок, награду и маску. Админские API не доступны DJ/модератору/участнику. Служебное имя запрещено при регистрации; бот имеет обычную роль USER, без пароля и без DJ.

Админка показывает текущий раунд, темы/ревизии, аудит импортов, историю по 30 раундов и рейтинг за текущий день в настроенном поясе. Выбор произвольного периода и отдельный аудируемый отзыв ошибочной награды остаются расширениями; прямую правку баланса не применять.

## Проверка

`npm run test:quiz` собирает API и запускает unit + интеграционные тесты. Интеграционные сценарии создают отдельную временную PostgreSQL-базу `tusova_quiz_test_<timestamp>`, API на 3127/3128, затем завершают свои процессы и удаляют только эту базу. По умолчанию допускается localhost; для локального Docker PostgreSQL из WSL укажите `QUIZ_TEST_LOCAL_DB_HOST=<локальный IP>` явным параметром окружения. На production эти тесты не запускать.
