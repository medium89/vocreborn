# Вход через Google, Яндекс, VK, Mail.ru и Telegram

## Подготовка сервера

1. Задайте стабильный ключ `OAUTH_ENCRYPTION_KEY` в окружении API: `openssl rand -base64 32`. Это 32 байта в base64. Храните ключ отдельно от репозитория и делайте резервную копию: при утрате сохранённые секреты приложений нельзя расшифровать.
2. Примените миграцию `20261015120000_social_auth` и перезапустите API/web. В production Compose ключ передаётся через `infra/docker-compose.prod.yml`.
3. В админке чата откройте «Система» → «Вход через соцсети». Для каждого провайдера скопируйте показанный адрес возврата, создайте приложение, внесите Client ID и Client Secret и включите вход. Пустой секрет при последующем сохранении сохраняет предыдущий.
4. Пока приложение не настроено и не включено, его значок на форме входа виден, но недоступен. Секреты в ответ API не возвращаются и хранятся в БД с AES-256-GCM.

## Приложения провайдеров

- [Google Cloud Console](https://console.cloud.google.com/apis/credentials): OAuth-клиент типа Web, права `openid email profile`.
- [Яндекс OAuth](https://oauth.yandex.ru/): приложение для авторизации, права `login:info login:email`.
- [VK ID](https://id.vk.com/about/business/go/docs/ru/vkid/latest/vk-id/connection/web/): приложение для сайта и точный redirect URI.
- [Mail ID](https://oauth.mail.ru/docs): OAuth-приложение с доступом `userinfo`.
- [Telegram Login](https://core.telegram.org/bots/telegram-login): через BotFather настройте Login Widget, разрешённые URL, Client ID и Secret; алгоритм подписи RS256 или ES256.

Все redirect URI задаются по отдельности для локальной и production-среды. Адрес страницы чата (`WEB_ORIGIN`) и публичный адрес API (`PUBLIC_API_URL`) должны быть корректны. Для локального входа допустим `localhost`; production должен использовать HTTPS.

## Аккаунты и приватность

- При первом входе пользователь обязан указать почту, ник и тег. Тег предлагается из части адреса до `@`, редактируется при регистрации и позже в профиле. Для VK/Telegram, которые могут не сообщить почту, она вводится на этом шаге и подтверждается письмом.
- Социальная идентичность привязывается по устойчивому ID провайдера, а не по совпадению адресов. Владельцы существующих аккаунтов подключают провайдера в «Мой профиль» → «Безопасность» → «Вход через соцсети». Автоматической привязки по почте нет.
- Вход использует одноразовое состояние, PKCE там, где он поддерживается, HttpOnly cookies и серверную проверку токена Telegram. Данные приложения доступны только администратору; секрет никогда не показывается после сохранения.
- Для полной проверки нужны реальные Client ID/Secret и тестовые аккаунты у каждого провайдера. Локальные интеграционные тесты проверяют настройки, шифрование, начало OAuth, привязку и завершение регистрации без внешних учётных данных.
