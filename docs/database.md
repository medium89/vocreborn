# База данных MVP

## Состав

PostgreSQL является источником истины. Prisma используется для схемы, миграций, типизированных запросов и seed-данных.

Основные таблицы:

- `users` — профиль, роль, статус и данные входа;
- `sessions` — серверные сессии с hash токена;
- `rooms` — публичные и приватные комнаты;
- `room_memberships` — участие и роль внутри комнаты;
- `messages` — публичные и личные сообщения;
- `mutes` и `bans` — ограничения и аудит модерации.

Сообщение обязано иметь ровно одно назначение: комнату или получателя. Пустой после trim текст запрещён ограничением базы.

## Локальный запуск

```bash
docker compose -f infra/docker-compose.yml up -d postgres
npm --prefix apps/api run db:deploy
npm --prefix apps/api run db:seed
```

Настройки подключения находятся в `apps/api/.env`; шаблон — в `apps/api/.env.example`.

## Разработка схемы

```bash
npm --prefix apps/api run db:generate
npm --prefix apps/api run db:migrate -- --name change_name
npm --prefix apps/api run db:studio
```

Начальная миграция: `apps/api/prisma/migrations/20260908000000_init/migration.sql`.

## Production

- пароль БД и DATABASE_URL передаются через secret manager;
- миграции применяются командой `prisma migrate deploy`;
- seed не запускается автоматически;
- порт PostgreSQL не публикуется наружу;
- резервное копирование проверяется восстановлением, а не только фактом создания backup.


## Восстановление доступа и модерация

- `recovery_codes` — устаревшая таблица прежнего механизма восстановления; активные API-маршруты к ней отключены, удаление будет выполнено отдельной миграцией вместе с email-восстановлением.
- `reports` содержит ровно одну цель — пользователя или сообщение, причину, статус, решение и обработавшего модератора.
- `moderation_audit` — append-only журнал решений по жалобам и ограничений пользователей.
- Внешние ключи целей жалоб используют `RESTRICT`, чтобы физическое удаление не разрушало историю; обычное удаление сообщений в чате остаётся мягким через `deleted_at`.
